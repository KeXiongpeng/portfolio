# Portfolio 项目 — 阿里云服务器部署手册

## 一、架构概览

```
用户浏览器
    │
    ├─ http://120.77.222.102:3000  ──→  my-web (Next.js 前端)
    │                                    │
    │                                    └─ API 请求 ──→  http://120.77.222.102:3001
    │                                                      │
    │                                                      ▼
    │                                                 my-server (NestJS 后端)
    │                                                      │
    │                                    ┌─────────────────┼─────────────────┐
    │                                    ▼                 ▼                 ▼
    │                               PostgreSQL          Redis         GitHub OAuth
    │                                (端口 5432)       (端口 6379)
    │
    └─ DNS生效后: https://kxpwty.cn  ──→  nginx-proxy (反向代理 + 自动HTTPS)
                                          │
                                          ├─ /           ──→  my-web  (端口 3000)
                                          └─ /api/*      ──→  my-server (端口 3001)
```

**项目包含三个子项目：**

| 子项目 | 技术栈 | 端口 | 说明 |
|--------|--------|------|------|
| `server/` | NestJS + TypeORM + PostgreSQL + Redis | 3001 | 后端 API |
| `web/` | Next.js 14 + Ant Design + Tailwind | 3000 | 前端网站 + 管理后台 |
| `miniprogram/` | 微信原生小程序 | — | 微信小程序（本手册暂不涉及） |

## 二、前置准备

### 2.1 阿里云资源清单

| 资源 | 说明 |
|------|------|
| ECS 服务器 | Ubuntu/CentOS，已安装 Docker |
| 域名 | `kxpwty.cn`（已实名认证） |
| 阿里云容器镜像服务（ACR） | 个人版，地域：深圳 |
| 阿里云镜像加速器 | `https://guha8sdi.mirror.aliyuncs.com` |
| GitHub OAuth 应用 | Client ID 和 Secret |

### 2.2 本地工具

- Docker Desktop（Windows）
- PowerShell
- SSH 客户端

### 2.3 安全组配置

在阿里云 ECS 控制台 → 安全组 → 配置规则 → 入方向，添加：

| 协议 | 端口范围 | 授权对象 | 描述 |
|------|---------|---------|------|
| TCP | 22 | 0.0.0.0/0 | SSH 登录 |
| TCP | 80 | 0.0.0.0/0 | HTTP |
| TCP | 443 | 0.0.0.0/0 | HTTPS |
| TCP | 3000 | 0.0.0.0/0 | 前端（临时，域名生效后可关闭） |
| TCP | 3001 | 0.0.0.0/0 | 后端 API（临时，域名生效后可关闭） |

> **重要**：80 和 443 是 nginx-proxy 使用的端口，域名生效后所有流量通过这两个端口进出，3000/3001 可以关闭。

## 三、服务器基础环境搭建

### 3.1 安装 Docker

```bash
# 安装依赖
yum install -y yum-utils device-mapper-persistent-data lvm2

# 添加阿里云 Docker 源
yum-config-manager --add-repo https://mirrors.aliyun.com/docker-ce/linux/centos/docker-ce.repo

# 安装 Docker
yum install -y docker-ce docker-ce-cli containerd.io docker-compose-plugin

# 启动并设置开机自启
systemctl start docker
systemctl enable docker
```

### 3.2 配置镜像加速器

```bash
# 创建 Docker 配置目录
mkdir -p /etc/docker

# 写入加速器配置（替换为你在阿里云控制台获取的专属地址）
cat > /etc/docker/daemon.json << 'EOF'
{
  "registry-mirrors": ["https://guha8sdi.mirror.aliyuncs.com"]
}
EOF

# 重启 Docker 使配置生效
systemctl daemon-reload
systemctl restart docker

# 验证配置
docker info | grep -A 3 "Registry Mirrors"
```

### 3.3 Docker 镜像拉取问题与解决方案

**问题**：国内服务器无法直接从 Docker Hub（`registry-1.docker.io`）拉取镜像，报 `not found` 或连接超时。

**原因**：Docker Hub 在中国大陆被运营商拦截或限速。阿里云镜像加速器可以加速小镜像（如 `alpine`），但大镜像（如 `postgres:400MB`、`redis:120MB`）仍然经常失败。

**解决方案：从本地 Windows 传输镜像到服务器**

这是最可靠的方式，绕开所有网络问题：

```powershell
# === 在本地 Windows PowerShell 执行 ===

# 1. 拉取镜像到本地（本地网络通畅）
docker pull postgres:15
docker pull redis:7
docker pull nginxproxy/nginx-proxy:latest
docker pull nginxproxy/acme-companion:latest

# 2. 导出为 tar 文件
docker save postgres:15 -o postgres-15.tar
docker save redis:7 -o redis-7.tar
docker save nginxproxy/nginx-proxy:latest -o nginx-proxy.tar
docker save nginxproxy/acme-companion:latest -o acme-companion.tar

# 3. 上传到服务器（约 600MB，需要几分钟）
scp postgres-15.tar root@120.77.222.102:/root/
scp redis-7.tar root@120.77.222.102:/root/
scp nginx-proxy.tar root@120.77.222.102:/root/
scp acme-companion.tar root@120.77.222.102:/root/
```

```bash
# === 在服务器 SSH 会话中执行 ===

# 4. 加载镜像
docker load -i /root/postgres-15.tar
docker load -i /root/redis-7.tar
docker load -i /root/nginx-proxy.tar
docker load -i /root/acme-companion.tar

# 5. 清理 tar 文件释放空间
rm -f /root/*.tar
```

## 四、基础设施容器部署

### 4.1 创建 Docker 网络

所有业务容器需要在一个共享网络中才能通过容器名互相访问：

```bash
# 业务容器网络（postgres、redis、server、web 共用）
docker network create app-network

# nginx-proxy 网络
docker network create nginx-proxy
```

### 4.2 启动 PostgreSQL

```bash
docker run -d \
  --name postgres \
  --restart unless-stopped \
  --net app-network \
  -e POSTGRES_PASSWORD=你的数据库密码 \
  -p 5432:5432 \
  -v /data/postgres:/var/lib/postgresql/data \
  postgres:15

# 等待启动后创建数据库
sleep 5
docker exec -it postgres psql -U postgres -c "CREATE DATABASE portfolio;"
```

### 4.3 启动 Redis

```bash
docker run -d \
  --name redis \
  --restart unless-stopped \
  --net app-network \
  -p 6379:6379 \
  -v /data/redis:/data \
  redis:7 redis-server --appendonly yes
```

### 4.4 启动 nginx-proxy 和 acme-companion

#### 这两个镜像的作用

**nginxproxy/nginx-proxy** 是一个自动化的 Nginx 反向代理：

- 自动监听 Docker 容器的启动和停止事件
- 当一个容器设置了 `VIRTUAL_HOST` 环境变量时，自动生成 Nginx 配置
- 无需手动编写 Nginx 配置文件

例如启动一个容器：
```bash
docker run -e VIRTUAL_HOST=api.kxpwty.cn my-app
```
nginx-proxy 会自动将 `api.kxpwty.cn` 的请求转发到这个容器。

**nginxproxy/acme-companion** 是自动 SSL 证书管理器：

- 配合 nginx-proxy 工作
- 当容器设置了 `LETSENCRYPT_HOST` 环境变量时，自动申请 Let's Encrypt HTTPS 证书
- 证书自动续期，无需手动管理
- 需要 nginx-proxy 已运行

**两者组合的效果：**
- 启动新容器只需设置 `VIRTUAL_HOST` 和 `LETSENCRYPT_HOST`
- 反向代理和 HTTPS 证书全自动
- 一个服务器可以运行多个 Web 应用，各自独立域名

#### 启动命令

```bash
# 创建数据目录
mkdir -p /etc/nginx/certs /etc/nginx/vhost.d /usr/share/nginx/html

# 启动 nginx-proxy
docker run -d \
  --name nginx-proxy \
  --restart unless-stopped \
  --net nginx-proxy \
  -p 80:80 \
  -p 443:443 \
  -v /etc/nginx/certs:/etc/nginx/certs \
  -v /etc/nginx/vhost.d:/etc/nginx/vhost.d \
  -v /usr/share/nginx/html:/usr/share/nginx/html \
  -v /var/run/docker.sock:/tmp/docker.sock:ro \
  nginxproxy/nginx-proxy:latest

# 启动 acme-companion
docker run -d \
  --name nginx-proxy-acme \
  --restart unless-stopped \
  --net nginx-proxy \
  -v /etc/nginx/certs:/etc/nginx/certs \
  -v /etc/nginx/vhost.d:/etc/nginx/vhost.d \
  -v /usr/share/nginx/html:/usr/share/nginx/html \
  -v /var/run/docker.sock:/var/run/docker.sock:ro \
  -e NGINX_PROXY_CONTAINER=nginx-proxy \
  -e DEFAULT_EMAIL=你的邮箱@qq.com \
  nginxproxy/acme-companion:latest
```

> **注意**：`-e NGINX_PROXY_CONTAINER=nginx-proxy` 必须添加，否则 acme-companion 找不到 nginx-proxy 容器会报错。

### 4.5 验证基础设施

```bash
docker ps
```

应看到 4 个容器运行：postgres、redis、nginx-proxy、nginx-proxy-acme。

## 六、本地构建 → 推送 ACR → 服务器拉取（完整流程）

### 6.1 后端（server）

#### Dockerfile 说明

```dockerfile
# server/Dockerfile
FROM docker.1ms.run/library/node:22-alpine AS builder   # 构建阶段
WORKDIR /app
COPY package*.json ./
RUN npm ci                                              # 安装所有依赖
COPY . .
RUN npm run build                                       # TypeScript 编译到 dist/

FROM docker.1ms.run/library/node:22-alpine              # 运行阶段（更小的镜像）
WORKDIR /app
COPY package*.json ./
RUN npm ci --production                                 # 仅安装生产依赖
COPY --from=builder /app/dist ./dist                   # 复制编译产物
EXPOSE 3001
CMD ["node", "dist/src/main.js"]                        # 启动入口
```

> **注意**：基础镜像使用 `docker.1ms.run/library/node:22-alpine`，这是国内可用的镜像加速地址。如果以后不可用，可替换为其他国内镜像源。

#### 构建和推送

```powershell
# === 本地 Windows PowerShell ===

# 1. 进入项目目录
cd "c:\Users\sun\Desktop\学习产出\server"

# 2. 构建镜像（替换为你的 ACR 地址）
docker build -t crpi-xxxxxx.cn-shenzhen.personal.cr.aliyuncs.com/my-project-portfolio/server:v1.0.0 .

# 3. 推送到 ACR
docker push crpi-xxxxxx.cn-shenzhen.personal.cr.aliyuncs.com/my-project-portfolio/server:v1.0.0
```

#### 服务器拉取和启动

```bash
# === 服务器 SSH ===

# 1. 拉取镜像
docker pull crpi-xxxxxx.cn-shenzhen.personal.cr.aliyuncs.com/my-project-portfolio/server:v1.0.0

# 2. 启动容器（IP 方式，无 HTTPS）
docker run -d \
  --name my-server \
  --restart unless-stopped \
  --net app-network \
  -p 3001:3001 \
  -e NODE_ENV=production \
  -e DATABASE_HOST=postgres \
  -e DATABASE_PORT=5432 \
  -e DATABASE_USER=postgres \
  -e DATABASE_PASSWORD=你的数据库密码 \
  -e DATABASE_NAME=portfolio \
  -e REDIS_HOST=redis \
  -e REDIS_PORT=6379 \
  -e JWT_SECRET=生产环境JWT密钥-请使用随机字符串 \
  -e FRONTEND_URL=http://120.77.222.102:3000 \
  -e GITHUB_CALLBACK_URL=http://120.77.222.102:3001/api/auth/github/callback \
  -e GITHUB_CLIENT_ID=你的GitHub_Client_ID \
  -e GITHUB_CLIENT_SECRET=你的GitHub_Client_Secret \
  -e SYNC_DB=true \
  crpi-xxxxxx.cn-shenzhen.personal.cr.aliyuncs.com/my-project-portfolio/server:v1.0.0

# 3. 查看启动日志
sleep 5
docker logs my-server
```

> **关键点**：
> - `--net app-network` 让后端容器能通过容器名 `postgres` 和 `redis` 访问数据库
> - `DATABASE_HOST=postgres` 使用的是 Docker 容器名，不是 IP
> - `SYNC_DB=true` 首次启动时自动同步数据库表结构（生产环境后续可改为 false）

## 七、域名配置与 HTTPS

### 7.1 当前问题：域名无法使用

**域名 `kxpwty.cn` 是 2026-07-30 新注册的，DNS 传播可能需要几小时到 48 小时。**

检查 DNS 是否生效：

```bash
nslookup kxpwty.cn 8.8.8.8
nslookup api.kxpwty.cn 8.8.8.8
```

如果返回 `NXDOMAIN`，说明 DNS 还未生效，继续等待。

### 7.2 域名解析配置

在阿里云域名解析控制台添加：

| 记录类型 | 主机记录 | 记录值 | TTL |
|---------|---------|--------|-----|
| A | @ | 120.77.222.102 | 600 |
| A | api | 120.77.222.102 | 600 |
| A | www | 120.77.222.102 | 600 |

- `@` → `kxpwty.cn`（主域名）
- `api` → `api.kxpwty.cn`（后端 API）
- `www` → `www.kxpwty.cn`（前端网站）

### 7.3 DNS 生效后切换到域名方式

**第一步：更新 GitHub OAuth 回调地址**

去 GitHub Developer Settings 更新 Authorization callback URL：
- 从 `http://120.77.222.102:3001/api/auth/github/callback`
- 改为 `https://api.kxpwty.cn/api/auth/github/callback`

**第二步：停止 IP 方式的容器**

```bash
docker stop my-server my-web
docker rm my-server my-web
```

**第三步：用域名方式重新启动**

```bash
# 后端
docker run -d \
  --name my-server \
  --restart unless-stopped \
  --net app-network \
  --net nginx-proxy \
  -e NODE_ENV=production \
  -e VIRTUAL_HOST=api.kxpwty.cn \
  -e LETSENCRYPT_HOST=api.kxpwty.cn \
  -e DATABASE_HOST=postgres \
  -e DATABASE_PORT=5432 \
  -e DATABASE_USER=postgres \
  -e DATABASE_PASSWORD=你的数据库密码 \
  -e DATABASE_NAME=portfolio \
  -e REDIS_HOST=redis \
  -e REDIS_PORT=6379 \
  -e JWT_SECRET=生产环境JWT密钥 \
  -e FRONTEND_URL=https://kxpwty.cn \
  -e GITHUB_CALLBACK_URL=https://api.kxpwty.cn/api/auth/github/callback \
  -e GITHUB_CLIENT_ID=你的GitHub_Client_ID \
  -e GITHUB_CLIENT_SECRET=你的GitHub_Client_Secret \
  crpi-xxxxxx.cn-shenzhen.personal.cr.aliyuncs.com/my-project-portfolio/server:v1.0.0

# 前端
docker run -d \
  --name my-web \
  --restart unless-stopped \
  --net app-network \
  --net nginx-proxy \
  -e NEXT_PUBLIC_API_URL=https://api.kxpwty.cn \
  -e VIRTUAL_HOST=kxpwty.cn,www.kxpwty.cn \
  -e LETSENCRYPT_HOST=kxpwty.cn,www.kxpwty.cn \
  crpi-xxxxxx.cn-shenzhen.personal.cr.aliyuncs.com/my-project-portfolio/web:v1.0.0
```

> **关键变化**：
> - 添加 `--net nginx-proxy` 让 nginx-proxy 能发现这个容器
> - 添加 `VIRTUAL_HOST` 和 `LETSENCRYPT_HOST` 触发自动反向代理和 SSL 证书申请
> - 去掉 `-p` 端口映射（通过 nginx-proxy 的 80/443 端口访问）
> - `NEXT_PUBLIC_API_URL` 改为 HTTPS 域名

> **注意**：Docker 容器只能加入一个网络。如果需要同时加入 app-network 和 nginx-proxy，先启动容器后再用 `docker network connect` 手动添加第二个网络。

**第四步：等待 SSL 证书签发**

acme-companion 会自动申请 Let's Encrypt 证书，通常需要 1-5 分钟。查看进度：

```bash
docker logs -f nginx-proxy-acme
```

看到 `Certificate obtained successfully` 表示证书签发成功。

**第五步：关闭临时端口**

在阿里云安全组中删除 3000 和 3001 的入方向规则，只保留 80 和 443。

### 7.4 验证

```bash
# 检查 HTTPS
curl -I https://kxpwty.cn
curl -I https://api.kxpwty.cn
```

浏览器访问：
- `https://kxpwty.cn` → 前端首页
- `https://kxpwty.cn/admin/login` → 管理后台
- `https://api.kxpwty.cn/api/projects` → API 接口

## 十、故障排查

### 问题 1：Docker 镜像拉取失败

**现象**：`failed to resolve reference "docker.io/library/xxx": not found`

**解决**：从本地 Windows 传输镜像（见 3.3 节）

### 问题 2：容器启动后 `ENOTFOUND postgres`

**现象**：`getaddrinfo ENOTFOUND postgres`

**原因**：容器不在同一个 Docker 网络中

**解决**：
```bash
docker network create app-network
docker network connect app-network postgres
docker network connect app-network redis
# 重新启动 my-server 时加 --net app-network
```

### 问题 3：HTTP 502 Bad Gateway

**排查步骤**：
```bash
# 1. 检查容器是否运行
docker ps

# 2. 检查容器内部是否正常
docker logs my-server
docker logs my-web

# 3. 检查本地是否可访问
curl http://localhost:3000
curl http://localhost:3001

# 4. 检查安全组是否开放端口
```

### 问题 4：DNS 不生效（NXDOMAIN）

**排查步骤**：
```bash
# 检查 DNS 解析
nslookup kxpwty.cn 8.8.8.8

# 检查域名 WHOIS 信息
whois kxpwty.cn

# 检查域名 NS 记录
dig NS kxpwty.cn @8.8.8.8
```

常见原因：
- 新注册域名 DNS 传播未完成（等待 1-48 小时）
- 域名未实名认证（国内 .cn 域名必须实名认证）
- DNS 服务器未指向阿里云（应在域名控制台修改为 `dns3.hichina.com` / `dns4.hichina.com`）

### 问题 5：SSL 证书申请失败

**排查**：
```bash
docker logs nginx-proxy-acme | grep -i error
```

常见原因：
- DNS 未解析到服务器 IP
- 80 端口未开放（Let's Encrypt 需要通过 80 端口验证域名）
- nginx-proxy 容器未运行
